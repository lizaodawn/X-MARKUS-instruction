01 About X-MARKUS

X-MARKUS is a search and information retrieval environment for text and image data annotated with ENTMARKUS, COMARKUS, and IMMARKUS.

It allows users to import and convert existing MARKUS annotations, browse and filter annotations within or across textual or image materials, and export filtered subsets of data for further analysis or reuse.

For more information, source code, and citation details, visit the information page.

The Interface

After launching X-MARKUS in your browser, use the icons on the left menu bar to access its main features:

▶: Opens the Converting interface for importing and converting annotation files.

: Opens the Searching and Filtering interface for browsing, querying, and filtering annotations.

: Opens the Visualizing Relations interface for exploring relationships among annotations, including relationships across combined text and image datasets.

: Opens the MUNDa platform for spatial analysis

: Opens the information page.

: Opens the help page.

02 Prerequisites and Data Preparation

Before using X-MARKUS, ensure your annotations have been properly created and checked in the MARKUS services.

  • ENTMARKUS: entity annotation in texts (persons, places, organizations, dates, and other semantic categories).
  • COMARKUS: contextual annotation that groups ENTMARKUS entities into structured clusters using a schema to establish relations and preserve context.
  • IMMARKUS: semantic image annotation that defines specific image regions using custom data models to establish relationships within and across images.

Folder Format

  • ENTMARKUS: working folder containing all your .html files
  • COMARKUS: working folder containing your .html files and their matching .json files, alongside xmarkus-metadata.json and rules.json
  • IMMARKUS: working folder containing all subfolders, IIIF Manifest .json files, alongside _immarkus.settings.json, _immarkus.model.json, _immarkus.relations.json and _immarkus.folder.meta.json

03 Converting Annotations

  1. Open X-MARKUS in your browser at https://xmarkus.xmarkus.org and click on the Converting icon ▶ on the left menu bar.

  2. Select the conversion option for your project: ENTMARKUS, COMARKUS, or IMMARKUS.

  3. Follow the instructions to upload your annotation files and convert them into a format suitable for X-MARKUS.

    4. Working with Entity Annotations (ENTMARKUS files)

    1. When converting ENTMARKUS files, select the files from your ENTMARKUS working folder. A dialog will then prompt you to specify a compilation metadata field. You can use the existing local folder name or enter a custom name.

    2. Once the conversion is complete, a summary displays the number of files processed for your compilation.

      From here, you can:

      • Add More Files to the conversion.
      • Go to Search and Filter to work with the converted annotations.
      • Download the converted .xmlfile for later use.
      • Merge Databases to combine converted files from COMARKUS and IMMARKUS.

    Working with Event Annotations (COMARKUS files)

    1. When converting COMARKUS files, a dialog will ask you to choose how annotations are displayed:

      • By event: Displays each event separately. A source text containing multiple events will be repeated for each event.
      • By source text: Displays each source text only once, grouping all associated events together in a side panel.

    2. After selecting a display mode and uploading all files from your COMARKUS working folder, you can add a "compilation" metadata field to specify the folder name. You can either use the existing local folder name or type a custom name.

      This is useful for distinguishing between multiple COMARKUS folders when converting and navigating them together in X-MARKUS.

    3. Once the conversion is complete, a summary displays the number of files processed for your compilation. There should normally be one metadata file per working folder.

      The number of entmarkus html and comarkus json files must match; if they do not, your COMARKUS working folder may have mismatched files. Check the folder, delete any unmatched files, and convert again.

      From here, you can choose to Add More Files, Go to Search and Filter, Download the converted .xmlfile for later use, or Merge Databases to combine converted files from COMARKUS and IMMARKUS.

    Working with Image Annotations (IMMARKUS files)

    1. When converting local IMMARKUS files, due to the explorer restrictions, you will need to select the same folder twice. Once the conversion is complete, a summary displays the number of images processed for your compilation.

      From here, you can choose to Add More Files, Go to Search and Filter, Download the converted .xmlfile for later use, or Merge Databases to combine converted files from COMARKUS and IMMARKUS.

    2. There is an advanced mode for converting IMMARKUS files using standard URLs. By hosting your IMMARKUS folder on a web server, you give each image a stable, reusable address. This allows X-MARKUS to reload the images reliably after conversion and makes it easier to share the converted .xml file with others who use the same server settings. The advanced mode also supports direct URLs to files hosted on remote servers.

      Using standard URLs gives each IMMARKUS image a stable, reusable address. This allows X-MARKUS to reload the images reliably after conversion and makes it easier to share the converted database with others.

      The default local configuration uses Simple Web Server.

      Click to read the instructions for setting up a Simple Web Server for your IMMARKUS files.

      Purpose

      When you upload local images from your IMMARKUS project folder to X-MARKUS, the browser only creates a temporary link. If you refresh the page, this link breaks and the image path is lost.

      You can solve this by setting up a simple local web server to generate stable URLs for your images. As long as the server application is running on your computer, your images will load reliably in the X-MARKUS interface without dropping.

      This setup also makes sharing your work much easier. You can send your exported XML file and the corresponding image folder to a colleague. As long as they maintain the exact same relative folder structure (starting from \XmarkusData\ImmarkusData\...) and run their own local server, X-MARKUS will successfully parse and load the source images on their machine.

      A. Install and set up folders

      1. Install Simple Web Server from https://simplewebserver.org/.
      2. Create a main folder, for example:
        C:\Users\xxxxx\Downloads\simple server test
        (* the folder name and location can be of your choice).
      3. Inside it create: XmarkusData\ImmarkusData.
      4. Copy your IMMARKUS project folders into: [your folder path]\XmarkusData\ImmarkusData.For example:
        C:\Users\xxxxx\Downloads\simple server test\XmarkusData\ImmarkusData\四川_annotation_rev_0608

      B. Start Simple Web Server

      1. Open Simple Web Server.
      2. Set "Folder path" = [your folder path].
      3. Set "Port" = 8088.
      4. In the dropdown menu of "Security", tick "Use HTTPS".
      5. Click "Create Server".
      6. Test in a browser: go to https://localhost:8088/ and check that XmarkusData appears.

        * Your browser may display a security warning the first time you visit. You can safely bypass this by clicking Advanced > Proceed to localhost (unsafe). You will only need to do this once.



      1. To switch between regular and advanced mode, hold Ctrl (Windows) or Cmd (Mac) and click the outer grey border of the IMMARKUS conversion box.

      2. Click "Select an IMMARKUS project folder" and choose a folder under [your folder path]\XmarkusData\ImmarkusData.
      3. The IMMARKUS conversion box will now use URLs like: https://localhost:8088/XmarkusData/ImmarkusData/四川_annotation_rev_0608.
      4. Keep your web server running while you work; if images disappear, restart the server and reload the database.

    04 Merging Converted Annotations

    You can merge multiple converted annotations from COMARKUS and IMMARKUS into a single X-MARKUS database file. This is useful for working with different source types, such as textual event annotations and image annotations, in one integrated database for comparison and cross-source analysis.

    You can initiate a merge in two ways:

    • Click Merge Databases immediately after both the COMARKUS and IMMARKUS conversions are complete.

    • Or click the Merge DBs button on the top menu bar to combine previously converted and downloaded .xml files.

    05 Searching and Filtering Annotations

    After converting and merging your annotations, you can use X-MARKUS to search and filter across text entities, contextual clusters, and image annotations.

    Importing Annotations

    Import your converted annotations into Searching and Filtering interface in one of the two ways:

    • Click Go to Search and Filter directly from the Converting interface.

    • Or click the Searching icon on the left menu bar, then click Import on the top menu bar to load a previously downloaded .xml file.

    Navigating Annotations

    Sources and annotations are displayed in parallel panes:

    • Filter Pane: Filter your text and image annotations by metadata, annotated event tags and their categories and normalizations, or entities. For image annotations, you can additionally filter by annotated properties. For more details, see Filter Options.

      • After selecting your criteria from the drop-down menu, click Apply Filter at the bottom of the pane to apply them. You can also click Select All to select all available options, or click Invert to invert your selections.

      This pane uses a hierarchical structure to help you progressively narrow your results. Click undo to revert your last selection, or Reset to clear all filters.

    • Source Pane: Displays the original text or image containing the annotations, with metadata shown at the top.

      • You can sort the displayed sources by:

      • File name (Document ID)
      • Author name
      • Compilation name defined during conversion (Compilation)
      • Gazetteer name (Data Source)
      • Inscription title (Piece Title)
      • Covering place (Place Covered)
      • Publication year in ascending or descending order

      For event annotations, the COMARKUS color scheme and ENTMARKUS IDs are integrated directly into the text. You can activate this display via the drop-down menu in the top right corner.

    • Annotation List Pane: Displays the tags associated with each piece of text or image.

      • For event annotations, click higilight event tags at the top of the pane to show all tags in the text, or click individual tags in the list to highlight them selectively.

      For image annotations, shapes are highlighted on the source image by default. Click Toggle all shapes to show or hide them at once, or click specific shapes in the list to highlight them on the image.

    Filter Options

    The filter pane provides different filtering criteria for text and image annotations. The available options depend on the annotation type and are organized hierarchically, allowing you to refine your selections from broad categories to more specific values.

    Filter Options for Text Annotations

    For ENTMARKUS annotations, you can filter by Entity Tags(text_tags): defined in ENTMARKUS, such as "action" and "soccat".

    For COMARKUS annotations, except for the Entity Tags (text_tags), you can also filter by:
    • Metadata (metadata): Default parsed metadatafields from the converted dataset, including "author", "data source" (gazetteer title), "data title" (inscription title), "place covered", and "publication year".

    • User defined metadata (udef_docmeta): Custom metadata fields defined in COMARKUS, such as "piece_time", "source_time" etc.

    • Event tags (txt_event_tree): Event tags defined in COMARKUS, such as "EVENT" and "INITIATOR".

    Filter Options for Image Annotations

    For IMMARKUS annotations, you can filter by:
    • Metadata (metadata): Default parsed metadata fields from the converted dataset, including "author", "compilation" (image folder name), "piece title" (image title), "place covered", and "publication year".

    • User defined metadata (udef_docmeta): Custom metadata fields defined in IMMARKUS, such as "Genre" and "Medium" etc.

    • Image Entity Classes(img_entity_tree / Udef_Img_EntityClass): Entity classes defined in IMMARKUS, such as "object" and "temple".

    • Relationships between Image Entities(img_entity_tree / Udef_Img_EntityRelation): Relationships between image entities defined in IMMARKUS, such as "crossing".

    • Image Properties(img_properties): Properties associated with entities annotated in IMMARKUS, such as "relation_to_wall", "texture" and "direction".

    Entities in Both Text and Image Annotations

    For the RegInfra project, X-MARKUS also supports filtering infrastructure entities that occur in both text and image annotations. Use the Event-Image Alignment (align_evt_img) filter to identify corresponding entities in bridges or city walls.

    The filter displays the IDs of entities that occur in both annotation types in a drop-down menu. Select one or more IDs to retrieve the corresponding text and image annotations.

    Editing Conditions in Query Bar

    In addition to using the filter pane, you can type directly into the query bar to search for both in-text keywords and annotation tags.

    • Search operators:The query bar supports exact and partial matches. Use a space for AND, and a pipe (|) for OR.

      • For example, in a combined corpus of inscriptions and maps, typing stone|flag_stone_layoutsearches across both text and image annotations. It returns sources containing either stone or flag_stone_layout.

    • Regular expressions: For advanced searching, you can use regular expressions by prefixing your query with regexp:.

      • For example, entering regexp:捐.{0,7}兩 finds sources with zero to seven characters between "捐" and "兩", helping you locate specific funding records.

    Grouping Filtered Annotations for Subset

    With the Bag feature, you can group filtered results into a custom subset for further analysis or export.

    1. Apply your desired filters in the filter pane or search conditions in the query bar.

    2. Click + in the top right corner to add these results to the Bag.

    3. Apply new filters or search conditions, and use + or - to add or remove those results from the existing Bag, or click C to clear the bag entirely.

    4. You can also remove individual items from the Bag by clicking the bag icon next to a text or image title.

    5. Click fetch to retrieve and view the results currently in your Bag.

    Visualizing and Exporting Filtered Annotations

    After filtering annotations, or retrieving a subset from the Bag, use the top menu bar to continue working with the current results:

    • Fetch to Visualizing Relations: Click viz relations to visualize the relationships between annotations and perform complex graph queries.

    • Export as .xml: Click export xml to download the current results as an .xml file for further analysis or sharing.

    06 Visualizing Relations

    You can use Visualizing Relations to explore connections within a single annotation dataset or across combined text and image annotatioin datasets.

    Importing Annotations

    You can import your dataset into the Visualizing Realtions interface in either of the following ways:

    • From the Searching and Filtering page, click viz relations to fetch the current dataset. If the dataset is large, the interface may initially display a blank graph. The data has still been loaded. You can set filter conditions and click Redraw to generate the relation graph.
    • Or click the Network icon on the left menu bar, then click Import on the top menu bar to load a previously downloaded .xml file.

    Querying across datasets

    The knowledge graph supports queries based on shared entities, entity properties, and metadata fields. This allows you to connect related information across different image projects, textual datasets, or combined text and image corpora.

    Combining query conditions

    You can combine several conditions in one query. For example, you can match a piece title in a textual source with a stele title in an image source and require the same author identifier in both sources. The graph then displays the sources that meet the query conditions together with the relevant features extracted from their annotations.

    Filtering the graph

    Use the filter panel on the right to refine the graph:

    • Set a time range for event nodes.
    • Include or exclude events without time information.
    • Add tag-feature filters and select the relevant node type.
    • Combine multiple tag-feature conditions.
    • Remove nodes without connections.
    • Display connected feature-hierarchy nodes.
    • Preserve node positions when redrawing the graph.

    Redrawing and resetting

    After setting the desired conditions, click Redraw to update the graph. Click Clear All Filters to remove the filter conditions. You can also click Reset to restore the initial view.

    Exporting the graph

    Use SVG to export the graph as an SVG image, or XML to download the graph data as an .xml file. You can also follow links in the graph to open the relevant sources or events and inspect their underlying annotations.
